## Aesthetic reference

- **Standard:** Stripe <!-- Linear | Stripe | Apple Native | Raycast | Notion | Custom -->
- **Notes:**
  Baseline color/type system is the official **MK** ("The Escalate") brand manual, not the current `src/theme.css` (red `#dc2626` / navy / Instrument Serif) — that file is due for a refresh to match. Stripe governs density, elevation, and data-table/card clarity; MK governs the palette and type:
  - Color: `paper #f6f6f6` (page bg), `surface #ffffff` (cards), `ink #141414` (primary text), `ink-body #333333` (secondary text), `rule #dcdcdc` (borders), `wine #7a1e3e` (primary accent / CTAs — 9.3:1 on paper), `signal #d10f2c` light / `#de0533` dark-surface (reserved for the single most urgent element on a screen — never decorative), status vocabulary `status-segera #a8101f` (urgent), `status-sahkan #7a4f00` (verify), `status-sedia #0b5e37` (ready), `status-ketahui #1f4fa8` (informational), phase gradient `phase-1..4` (`#8c2a4e → #7a1e3e → #5e1530 → #3e0d20`).
  - Type: Inter (sans, body/headings, 400–800) + JetBrains Mono (labels, data, running-heads, uppercase). No script or decorative display face.
  - Elevation/shape: Stripe-style layered shadows (`0 1px 2px rgba(20,20,20,.04), 0 2px 10px rgba(20,20,20,.06)`) on cards (10–14px radius); buttons fully pill-shaped (`border-radius: 9999px`); brand structural elements (section bars, phase cards) stay sharp-edged per the MK manual.
  - Reference implementation: the Command Centre / First 60 Minutes / Landing mockups built this session (Artifact canvas) are the working example of this system applied to real screens.

## Banned anti-aesthetics

- Gratuitous glassmorphism / `backdrop-filter` without a high-contrast boundary
- Floating pastel pill badges for ordinary metadata
- Arbitrary decorative gradients and neon glowing borders
- Multi-color radial rainbow gradients on standard CTAs
- Cartoon empty-state illustrations (people waving / high-fiving)
- Nested scrollbars and icon bloat inside inputs
- **Unicode glyphs or emoji as UI icons** (project-specific addition — `src/core/moduleConfig.ts` currently uses `⚡ ◆ ① ◎ ⏱ ✎ ☰ ☎ 📘` as module icons; replace with the recorded icon library on next touch)

## Accessibility target

- **Level:** WCAG 2.1 AA <!-- WCAG 2.1 AAA | WCAG 2.1 AA -->
- **Contrast:** >4.5:1 normal text, 3:1 large text (24px+) and borders/controls/icons. Never rely on color alone to distinguish states — pair with shape, label, or position (the MK status vocabulary already does this: ▲ segera / ◆ sahkan / ● sedia / ■ ketahui).
- **Touch / focus:** 44×44px minimum touch targets. Visible `:focus-visible` outline (2px `wine #7a1e3e`, 2px offset) on every interactive element — already implemented in this session's mockups; carry the same pattern into real components.

## Brand tone and microcopy voice

- **Voice:** Utilitarian & Minimal <!-- Utilitarian & Minimal | Warm & Humancentric | Opinionated & Direct -->
- **Capitalization:** Sentence case for UI copy and buttons
- **Notes:** The UI should disappear under pressure — this is crisis-response tooling used in the first 60 minutes of an incident, not a marketing surface. Task copy follows the MK manual's own rule: verb first, page/section reference last (e.g. "Namakan jurucakap tunggal dan sahkan talian kenyataan" / ref `A8 · 40`). Bilingual BM/EN throughout via the existing `t(en, bm)` helper pattern — write both, BM first.

## Agent rules

1. Read this profile before creating or editing any UI, CSS, or microcopy.
2. Prefer skills by task: new page → `page-patterns` (name the pattern before markup); layout / chrome → `viewports`; forms → `forms`; overlays → `surfaces`; loaders → `loaders`; empty views → `empty-states`; motion → `motion`. Before finishing UI, run `ux-audit`.
3. Use only the recorded icon library (or project SVG path). Do not mix icon sets or use emoji as UI icons.
4. Never introduce items on the banned list.
5. Destructive actions always use an explicit confirmation dialog.
